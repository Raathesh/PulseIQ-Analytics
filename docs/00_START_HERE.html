📊 Welcome to PulseIQ

The workforce analytics and BI cockpit of Aura Workforce.

Your mission

A founder should not need four reports to know how the business is doing. PulseIQ builds a trusted warehouse, clear metrics and dashboards that connect headcount, pay, cost, cash and productivity in one place, with privacy built in.

In four weeks you will: You will build a star-schema analytics warehouse with data-quality gates, a governed metric layer, dashboards for people, finance and teams, an executive company-health scorecard, automated reports and a hosted self-service experience. Your numbers are validated against answer keys inside the dataset.

You are part of one product

Six tracks, one fictional client (Zenith Nova Technologies, 745 people on record, 18 months of payroll). Each track builds its own piece of Aura Workforce and ships it independently.

Your first 30 minutes

  • Open 01_Project_Overview.html and read the whole page once.
  • Install: Python 3.11 or newer and DuckDB; One BI path: Streamlit, Power BI Desktop, Tableau Public or Metabase; Git and a GitHub account.
  • Create a private GitHub repository for your project and add this kit's starter material.
  • Open 02_Task_Playbook.html and start task 1 straight away.

The 4-week calendar

Phase 1 · Build the BaseTasks 1–5
Phase 2 · Core FeaturesTasks 6–10
Phase 3 · Advanced DepthTasks 11–15
Phase 4 · Go-Live & SubmitTasks 16–20

Finish about five tasks a week. Week 4 is for going live and polishing; do not leave deployment to the last day.

Working rules

  • One Git branch per task, small commits, a clear message, a pull request you review yourself.
  • Fill DAILY_LOG.md every working day (5 lines: done, doing, blocked).
  • Every Friday record a 2-minute demo using WEEKLY_DEMO_CHECKLIST.md.
  • Everything in this kit is fictional training data. Never use real personal data.
  • Answer keys (the vault) are opened only after you finish the matching task. Using them early removes your own learning.
  • You own your work. Use any learning resource you like, but you must be able to explain every line in your demo.
