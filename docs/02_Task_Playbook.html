📊 PulseIQ Task Playbook

Step-by-step guidance for all 20 tasks, so you can finish alone.

How to use this playbook. Work in order. Open a task, follow the steps, tick every 'done when' line, then do the Level-up if you have time. Each task is a ticket: do it on its own Git branch and commit the result. You never need another track, a mentor or a company system to finish: everything you need is in this kit.

PQ-01ETL Pipeline & Data ContractsBasicWeek 1

Goal

Load the raw fact exports with a repeatable pipeline that validates every column against its contract.

Use

All fact sheets, data_contracts

Steps

  1. Run python load_to_duckdb.py from 05_Starter (or load the CSVs into PostgreSQL)
  2. Read data_contracts for each feed
  3. Write a Python or SQL step that checks every column against its contract (type, nullable, allowed values)
  4. Rejected rows go to a quarantine table with the reason
  5. Log row counts in and out

You are done when (Core)

  • Pipeline runs end to end from one command
  • Rejected rows are counted and explained

Level-up (optional)

Make it incremental (only new months)

Watch out

Never silently drop rows. Count them

Deliver

Go-Live guide

Your goal: a public dashboard link that opens for a stranger, loading from a hosted warehouse or data file, with a refresh routine.

Options

  • Recommended path A: Streamlit app (Python) with DuckDB or Parquet files, deployed free on Streamlit Community Cloud from your GitHub repo.
  • Path B: Tableau Public or Power BI publish-to-web for a no-code link (the data here is fictional, so public sharing is acceptable; check each tool's current rules).
  • Path C: Metabase or Superset in Docker on a small VPS (more control, more work).

Steps

  1. Export your final warehouse tables to Parquet or load them into a hosted database.
  2. Put the app and a small requirements.txt in the repo. Keep data files under the platform's size limit (aggregate if needed).
  3. Deploy from GitHub. Set secrets in the platform, never in code.
  4. Add a scheduled refresh (GitHub Actions cron that re-builds the data files and commits them, or the tool's refresh feature).
  5. Test on a phone and with someone who has never seen the project.
  6. Hide groups smaller than the minimum group size on the live site.

Common traps

  • Do not publish anything that looks like real people's data. Zenith Nova is fictional, but keep the privacy habits.
  • Large raw files can exceed free limits. Publish aggregates.
  • Write the data cut-off date on the dashboard.

When you are stuck

  • Step 1 (5 minutes): re-read the task and its steps. Most problems are one missed line.
  • Step 2 (10 minutes): read the exact error message from the top. Search it with the name of the tool.
  • Step 3 (10 minutes): shrink the problem: does the smallest possible example work? What changed since it last worked?
  • Step 4: write your question with STUCK_HELP_TEMPLATE.md (goal, what you tried, exact error, what you expected). Ask a peer in your track or search forums.
  • Step 5: park it, do the next task's Core, return later. A day away fixes many bugs. Note it in your daily log.
  • Never copy a solution you cannot explain. If you cannot explain it in your demo, it earns no marks.
